# The open-hurdle ledger

Every design note in `DESIGN.md` ends with a list headed "deferred, with what
un-defers each". There are nine of those lists, spread over five sections, and
nothing collects them — so scoping a slice has meant re-reading all nine to find
out which trigger the corpus is nearest to. This file is the collection. It adds
one column the notes cannot carry: **the measured distance from each trigger, as
of a date**, taken with `refinery corpus` where a number exists.

Three rules for keeping it honest:

- **An entry here points at the paragraph that argued it.** The argument stays in
  `DESIGN.md`; this file never re-argues a deferral, it only says where the plant
  stands relative to it. If the two disagree, the note is right and this file is
  stale.
- **A deferral without a written trigger is a gap, and is marked as one** rather
  than given a trigger invented here. Three of them are below.
- **When a slice takes an item, strike it with the slice's name** rather than
  deleting the row. The record of what was deferred and for how long is part of
  what the ledger is for.

Distances measured 2026-09-02 on the fourteen shipped scenarios, 6 000 ticks,
release build, unless a row says otherwise. **`scenarios/` holds fifteen files as
of M10.1**; rows whose distance predates it say so, and the two that M10.1
re-measured (A3, E1) carry the new number. **B1 and B3 were re-measured
2026-09-06** at the M10 close-out, on all fifteen and both fidelities, and both
of their old distances were wrong — B1's because it compared a pressure against
zero rather than against a vapour pressure, B3's because the state it says
nothing asks for arises during a run rather than at load, where its three
refusals look. **B15 was re-measured 2026-09-08** at M16.0, on all **nineteen** shipped files,
and its TRIGGER was rewritten because the old one could not be failed — see its
row and the last bullet of "Reading the ledger". **Its GAS clause was CLOSED
the same day by M16.2 (DESIGN §20)**, which ships the twentieth file —
`scenarios/fired_gas_drum.toml`, the only plant that selects
`[fidelity] heat_capacity = "linear"`. **`scenarios/` holds twenty files as of
M16.2**; every distance below that predates it was taken on nineteen or fewer. The A-section distances were
re-run the same day on nineteen plants (A3 confirmed at 920 of 5 000), the first
time since M9.1 they were measured rather than re-asserted.
**B13, B14 and B15 were measured 2026-09-07** at M14.0, on all
**seventeen** shipped files: B13 had never carried a number, and B14's and B15's
"Not measured" turned out to mean *waiting on an external citation* rather than
*not yet done* — see the comparative-trigger bullet under "Reading the ledger".

- **A trigger has to name what kind of node it is about.** B1's first draft would
  have fired immediately, because two product *tanks* are already below their
  bubble point — but a tank above its bubble point is a two-phase holdup (B3),
  not cavitation, which is a hydraulic-path phenomenon. Scoping the trigger to
  the flow path is what keeps B1 and B3 from claiming each other's evidence, and
  the exclusion had to be written down rather than assumed.
- **A row's proposed CHEAP FIX is a claim about the engine, and it goes stale
  the same way a distance does.** B3 said for a milestone that "a product cooler
  in the two files is a scenario defect and cheap", beside a distance that had
  been measured properly. Nobody built it. A cooler on a column draw is **refused
  at load on both column fidelities** — a draw line must end at a product store —
  so the cheap option was not a cheaper fix, it was a different deferral wearing
  the word "cheap". **Where a row offers two ways out, the cheap one is the half
  that has not been run**, because the expensive one is what the row exists to
  argue for.
- **The instrument error recurs a THIRD time, and the pattern is now the rule.**
  B1's 1.865× came from a script on a plant whose model refuses; B3's 0.30× came
  from the same script on the same plant. A number is a distance only if some
  engine configuration produces it — and if that configuration is not the shipped
  one, the row must say which edit reaches it and what else the edit moves. Here:
  one `thermo` line, 0 of 504 000 published floats, one extra diagnostic key on
  one furnace. That last clause is the part a "the flip is inert" summary drops.
- **Most of a scary-looking sweep was not evidence.** Ten of fifteen plants have
  a node below its bubble pressure. Five declare `phase = "gas"` cuts, where a
  liquid bubble-point test is meaningless by construction; two are columns, which
  are *at* their bubble point by definition; two carry an FCC `gas` lump with
  `tb = −40 °C` declared liquid, which is this table's B3 already. **Three of the
  four categories were exclusions**, and a sweep that reports the headline
  without them would have moved two rows on evidence that does not exist.
- **A note's site table is a hypothesis about which code is right, and both
  directions of error cost the same.** §16 fork 2 enumerated the five places that
  read "is a boil-off vent" as "is invisible" and marked three for work. It was
  wrong by one in each direction. `engine.rs:1036` is **correct and stays** — its
  skip is exactly what keeps the composition publish sweep from overwriting the
  vapour `y = K·x` with the emitting tank's liquid `x`, which is the defect M12.1
  exists to prevent. And the vent-FINDING site at `engine.rs:701`, which the note
  quotes only as the *precedent for the ownership rule*, is itself a receiver-side
  site: its `matches!(self.graph.node(nid).kind, NodeKind::Tank(_))` is
  **loop-invariant** — a question about the node, never about the edge — so on a
  recovery drum it reduces to "I am a Tank and this is a vent" and `.find` returns
  a SOURCE tank's vent. The drum would have published its own boil-off onto that
  tank's edge and written the flow over the rate the tank published moments
  earlier: M12.1's 2 539 kg bug, at the site whose comment records paying for it.
  **A fix that was right under one topology stops being right when the topology
  gains a case**, and a note citing that fix as a precedent is the most likely
  place to miss it.
- **An ordering property can be bought with a type instead of defended with a
  test.** §16 fork 3 names the trap — deciding a vent's emitting end from the
  edge's direction is "right today and wrong the moment a vent is ever stored the
  other way round" — and proposes to defend the convention with a fixture.
  Storing the emitter on the role (`LeakRole::BoilOffVent { emitter }`) makes a
  reversed vent a *correct* graph instead of a broken one, and the fixture becomes
  an assertion about behaviour rather than a tripwire around a comment. Same shape
  as M9.3b's `CascadeProfile`, where one `Option` over both halves made the
  falsified configuration unrepresentable.
- **A gate written against one member of a set can be falsified by the set.**
  §16 gate 3 asks that "the drum's contents are richer in the light cut than the
  emitting tank's". The demo has TWO emitting tanks on purpose, the heavier
  carries 2.3× the flow, and the inequality points the other way on the CORRECT
  engine: 0.2614 in the drum against 0.4971 in `naphtha_tank`. The reference that
  works is the flow-weighted mix of all the emitting liquids (0.1523), against
  which the drum is 1.72× richer and 44× leaner in the heaviest cut. The wording
  came from a one-emitter picture that the plant was never going to be.
- **An argument for a knob can be right about the knob and wrong about why.**
  §16 fork 4 justifies giving the recovery drum a heat sink on the grounds that
  "a drum with no cooling reaches its bubble point and re-vents everything: at
  steady state it recovers nothing". Measured over 6 000 ticks, an uncooled drum
  recovers **20.72%** — it **self-fractionates into a heavy pot**, boiling the
  light material straight back off until its own bubble point has climbed past
  435 K and it has stopped re-venting altogether. The knob still discriminates
  (20.72% → 42.52% at the shipped `UA` → 100% at 1e5 W/K), which is what M7.1's
  `smearing_k` rule actually demands, and the recovered fraction is **not
  monotone** in it at the low end. So the case for the condenser survives with a
  different sentence: not "otherwise nothing is recovered" but "otherwise half as
  much, and what is kept is the bottom of the barrel".
- **Adding an inert node to a plant is not bit-neutral, and only a control can
  say that.** The two emitting tanks on `crude_column_recovery` vent 8.7e-11 and
  1.2e-10 relative away from the same tanks on `crude_column_boiloff`, which
  looks like the routing having a side effect. Adding an inert `spare_tank` to
  `crude_column_boiloff.toml` — nothing piped to it, no `vent_to` anywhere on the
  plant — moves the same two figures by 7.1e-11 and 9.8e-10. A plant with one
  more node is a different plant at the last few bits. The mechanism is
  deliberately NOT pinned here (M9.1's rule about fitting one to a single
  observation); what the control establishes is only what the gate needed, that
  the emitting half of the engine is indifferent to where its vapour goes.
- **A refusal is only tested if the thing it refuses could otherwise have been
  built.** §16 fork 5 refuses a `Vessel` as a vent destination, and putting a
  vessel on the demo to prove it is refused ONE PASS EARLIER, for a different
  reason, with the right exit code: a vessel must hold a gas-phase composition
  (§3a) and the demo's slate is five liquid cuts. The gate passed while asserting
  nothing about fork 5. Same shape as M11.1's excluded nodes, one level up.
- **A coverage argument has to name what the new plant makes REACHABLE, not what
  it resembles.** B18 was written as "the machinery is exercised by the reorder
  gate and the cycle fixture, not by a chain", and everyone reading it — this
  file's own summary included — took a chain to be the missing exercise. It is
  not. `holdup_evaluation_order` is inert whenever declaration order already
  satisfies the vents, which is every file anyone would write, at every depth.
  What a chain buys is one narrower thing: a **transitive** constraint, so a
  reorder gate stops being passed by any implementation that merely pushes
  receivers to the end. **Measure the machinery on the plant you already have
  before claiming a new plant will exercise it** — the probe that found this cost
  one test and ran before a fork was written, and it changed what M15 claims
  rather than what M15 builds.
